> `SKIPPED_DUE_TO` 字段引用本台账 ID；波末/轮末批修按台账逐项闭环。

## 分诊规则（三路；规划 §6 失败协议）

见错先分诊，分诊结论写进台账 `分诊` 字段：

1. **基建抖动**——DO API 失败/建机失败/网络闪断/`P92 已知偶发`（42710 压缩与迁移
   down 死锁两签名：只在演练 fix PR 的测试门禁/全量轮可能出现——真机 NMS 只跑
   MigrateUp、生产无 compress_chunk、默认 7 天窗无块可压；与 #381 DB-03 不同根；
   命中→单包重跑定性已知偶发）。处置：记录、重试，**不计产品问题**。
2. **产品缺陷**——NMS/agent 代码行为与契约/预期不符。处置：记台账 + 污染面判定
   （同域后续场景 `SKIPPED_DUE_TO` 跳过、跨域继续收样本）；**带病继续**，轮末/波末
   批修：最小复现→本地先红→独立 PR（diff≤400）→栈式门禁→合并→按污染面重跑
   （第一部分整轮重跑；六波只重跑受污染场景+波末闸复跑，闸红升级整波）。
3. **四类致命才停**——NMS 崩溃不自启 / DB 不可达 / 收敛停滞超窗 / 安全面（凭据泄露、
   未预期开放面）。处置：立即停全演练，向用户报告，未定性前不动云资源。

## 台账字段

| 字段 | 说明 |
|---|---|
| ID | `ISS-NNN` 单调 |
| 现象 | 一句话可观察行为 |
| 证据 | 证据根相对路径（journal 段/API 快照/verdict 行/截图日志） |
| 疑似域 | NMS 域（discover/provision/collect/alert/dispatch/api/data…）或 agent/vpsctl/nmsctl |
| 污染面 | 受影响场景清单（→SKIPPED_DUE_TO 引本 ID）；无则写"无" |
| 致命否 | 四类之一填"是（哪类）"，否则"否" |
| 分诊 | 基建抖动 / 产品缺陷 / P92 已知偶发 |
| 状态 | open → 复现中 → 批修中（fix PR #）→ closed（重跑 PASS） |
